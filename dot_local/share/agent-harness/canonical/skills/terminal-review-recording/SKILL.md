name: terminal-review-recording
description: Record a watchable terminal demo with visible keys and typed prompts, offline selectable-text review, and MP4 playback.
---

Record the actual user path, not fake UI or accumulated screenshots.

1. Use synthetic data and owned isolated resources; keep outputs private. Read the application's isolated proof procedure. Obtain permission before touching owner sessions/devices.
2. Read the recorder's [input-overlay contract](../../../../terminal-review-recording/README.md#explicit-input-overlays). Use a real controlling PTY. When sending input, log **every key and typed prompt** as `{"time": 2.0, "kind": "text", "value": "/latency inspect"}` or `{"time": 2.1, "kind": "key", "value": "Enter"}`. Times are cast-relative; synchronize to recorded output rather than launcher startup. Do not infer input from screenshots or label an external API action as a keypress.
3. Use synthetic, disclosure-safe typing only. Keep raw input capture disabled. Never log real credentials or confidential prompts; recording output itself can still contain secrets. Do not type secrets into the captured session. If secret entry is unavoidable, stop recording and explicitly label the omitted step; do not pretend it was demonstrated.
4. Run `terminal-review-record --output-dir PRIVATE_NEW_DIR --size 48x32 --actions PRIVATE_ACTIONS_JSON -- COMMAND ARG...`. The driver must finish the action log before export. For a post-capture log, use `--export-only --actions FILE` before delivery. **Do not deliver an interactive demonstration without visible input annotations in both MP4 and offline HTML.** The labeled input band must not cover application text. Pace input for readability, wait for actual completion signals, hold the final frame for two seconds and exit normally. Closing keys must stay readable too: use an owned recorded wrapper that waits three real seconds after the client exits, then returns its exit status. Do not append invented cast time or freeze/retime old screenshots. Retain failures; clean up only owned resources.
5. Keep original `record.cast`. Add optional JSON chapters (`[{"time": 2.0, "label": "Actual action"}]`) with `--export-only --chapters FILE`; saved actions remain enabled. Never rewrite cast timing. Nonzero command/export status is failure, even with playable artifacts.
6. Check metadata versions/hashes, v3 duration, exit/no-input events and full movie decode. Verify actual overlay frames show typing, Enter, Escape and shortcuts at the correct times without obscuring responses. Browser-test offline HTML with network blocked: overlays must follow playback, forward/back seeks and chapter jumps, not remain stale when paused. Verify current-frame selection/copy preserves application row breaks, gaps and Unicode, with annotations clearly separate. Player 3.17.0 DOM extraction must be retested on upgrade; canvas-only graphics remain in cast/movie, not plain text. Missing, unreadable or misleading input overlays block delivery.
7. If phone delivery is requested, verify actual target-device playback, scrub/chapters, input overlays and text select/copy with the owner. Desktop emulation is not phone acceptance.
