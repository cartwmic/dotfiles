# Truth check (SKILL.md step 11)

`check_shape.py` checks structure only. This step checks that the lines each row cites show what the row says, with the codemap skill's claim checker: its scripts and check brief are called by path from the sibling skill `<codemap>` = `../deriving-readable-docs` (nothing is copied). Put the repo at the header's `commit:` first. A row with only `owner:` or history evidence has nothing to read and is listed as not checked.
1. `python3 -I <skill dir>/scripts/check_truth.py prepare REQUIREMENTS.md --out work` writes `work/register-claims.md` (one claim a row; a README or doc source is named in the sentence) and `work/rows.json`. It reads every `path:line` in a row's evidence cell (a `commit:`, `pr:` or `issue:` part never reaches the line checker; a row with only those is listed as not checked), backticked or followed by a remark. Parts are `;`-separated. A row whose cell has no citation, no `owner:` part and no history ref fails: prepare prints it, exits 1, and `verdicts` counts it as a failure.
2. `python3 -I <codemap>/scripts/check_citations.py work/register-claims.md <repo>` must exit 0. A line the file lacks, or a number or quoted name the cited lines do not hold, fails the row here, before any checker is briefed. Fix the row and run step 1 again.
3. `python3 -I <codemap>/scripts/slice.py work/register-claims.md <repo> --out work/slices`. One fresh Opus checker session per slice (not the register's writer) gets `<codemap>/references/check-brief.md` as written, its claims file, the repo and its flags file, and saves its report in `work/reports/`. When `prepare` reports owner-requirement rows, the checker also gets `<skill dir>/references/check-brief-owner-rows.md` and `work/owner-notes.txt` (see Owner-interview rows below).
4. `python3 -I <codemap>/scripts/score.py work/reports --repo <repo> --slices work/slices` rejects a report that skips a claim or reads no real line. Then `python3 -I <skill dir>/scripts/check_truth.py verdicts work work/reports` prints one verdict per row and exits 1 unless every checked row HOLDS.
5. Fix each WRONG, OVERSTATED or UNSUPPORTED row (correct the evidence, narrow the requirement, or cut it), then run steps 1 to 4 again and `check_shape.py` and `check_history_refs.py`. At most two fix rounds, and only checker rounds count: a rerun of `check_citations.py` (step 2) does not; report the rows that still fail. Note the rounds in the Run log.

## Owner-interview rows

A row whose evidence includes `owner:interview` states what the owner requires, not what the code does today. Judge whether the row's sentence and its note, read together, describe truly how far the cited code meets that requirement, including what it does not meet. A sentence that plainly states the owner's requirement and says the code does not meet it HOLDS if the cited code shows the gap.

The checker cannot judge this from the sentence alone, so `prepare` ends the last sentence of such a row with `(owner requirement)` and writes its note to `work/owner-notes.txt`, one line `N | R-id | note` with N the doc line of the row. A row with two sentences gives the checker two claims, `N.1` and `N.2`, and the tag is on the last only, so the addendum tells the checker to judge every claim on a listed line with the note. The note stays out of the sentence on purpose: `check_citations.py` fails a sentence whose number or quoted name the cited lines lack, and a note carries dates and file names. The checker reads both under `references/check-brief-owner-rows.md`, which gives the rule above and leaves the codemap brief as written.

## History refs (run every time, from SKILL.md step 10)

`python3 -I <skill dir>/scripts/check_history_refs.py REQUIREMENTS.md REPO` resolves every `commit:`, `pr:` and `issue:` ref. A commit must exist and be an ancestor of the snapshot commit (`--commit SHA`, else the header's). A PR or issue is read with `gh`: one gh says does not exist is UNRESOLVED; with no `gh`, or a gh that cannot run (not signed in, no network), it is NOT CHECKED and the output says so. It exits 1 on any UNRESOLVED ref: fix the ref. A row whose refs all resolve is reported as "resolved, claim not read-checked".
