# Truth check (SKILL.md step 11)

`check_shape.py` checks structure only. This step checks that the lines each row cites show what the row says, with the codemap skill's claim checker: its scripts and check brief are called by path from the sibling skill `<codemap>` = `../deriving-readable-docs` (nothing is copied). Put the repo at the header's `commit:` first. A row with only `owner:` or history evidence has nothing to read and is listed as not checked.
1. `python3 -I <skill dir>/scripts/check_truth.py prepare REQUIREMENTS.md --out work` writes `work/register-claims.md` (one claim a row; a README or doc source is named in the sentence) and `work/rows.json`. It reads every `path:line` in a row's evidence cell (a `commit:`, `pr:` or `issue:` part never reaches the line checker; a row with only those is listed as not checked), backticked or in a comma list or followed by a remark. A row whose cell has no citation, no `owner:` part and no history ref fails: prepare prints it, exits 1, and `verdicts` counts it as a failure.
2. `python3 -I <codemap>/scripts/check_citations.py work/register-claims.md <repo>` must exit 0. A line the file lacks, or a number or quoted name the cited lines do not hold, fails the row here, before any checker is briefed. Fix the row and run step 1 again.
3. `python3 -I <codemap>/scripts/slice.py work/register-claims.md <repo> --out work/slices`. One fresh Opus checker session per slice (not the register's writer) gets `<codemap>/references/check-brief.md` as written, its claims file, the repo and its flags file, and saves its report in `work/reports/`.
4. `python3 -I <codemap>/scripts/score.py work/reports --repo <repo> --slices work/slices` rejects a report that skips a claim or reads no real line. Then `python3 -I <skill dir>/scripts/check_truth.py verdicts work work/reports` prints one verdict per row and exits 1 unless every checked row HOLDS.
5. `python3 -I <skill dir>/scripts/check_history_refs.py REQUIREMENTS.md REPO` resolves every `commit:`, `pr:` and `issue:` ref (a PR or issue needs `gh`; without it they are listed unresolved). It exits 1 when a commit does not resolve: fix the ref. A row whose refs all resolve is reported as "resolved, claim not read-checked".
6. Fix each WRONG, OVERSTATED or UNSUPPORTED row (correct the evidence, narrow the requirement, or cut it), then run steps 1 to 4 again and `check_shape.py`. At most two fix rounds; report the rows that still fail. Note the rounds in the Run log.
